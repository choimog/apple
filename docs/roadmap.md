# 1단계 👤 `db/archive_schema.sql` 실행 · **1분 · 제일 급함**

**왜:** 보관 기능이 "어느 날짜를 어디에 옮겼고 언제 사라지는지" 를 적어 둘
표가 필요합니다. 이 표가 없으면 매주 화요일 보관 작업이
`보관 기록표(archives)가 아직 없습니다` 만 남기고 아무것도 안 합니다.

**하는 법**

1. https://supabase.com/dashboard → 우리 프로젝트
2. 왼쪽 **SQL Editor** → **New query**
3. 저장소의 [`db/archive_schema.sql`](../db/archive_schema.sql) **전체**를 복사해서 붙여넣기
4. **Run**

**확인:** 아래처럼 한 줄짜리 표가 나오면 정상입니다.

| 표 이름 | rls_켜짐 | 읽기규칙 |
|---|---|---|
| archives | true | 1 |

> ⚠️ **여러 번 실행해도 안전합니다.** 데이터는 하나도 안 바뀝니다.
> 이미 한 번 하셨더라도 **한 번 더** 해주세요 — 2026-08-09 에 칸이
> 하나 늘었습니다(`saved_at`). 있는 자료는 그대로 두고 칸만 더합니다.

# 2단계 👤 `SUPABASE_ANON_KEY` 등록 · 3분

**왜:** 지금 자동 검사에서 이 문구가 계속 뜹니다.

```
ℹ️ 화면 열어보기를 건너뜁니다.
```

**실제 데이터로 모든 화면을 열어보는 검사가 꺼져 있습니다.**
조회문 검사는 돌지만, "화면이 실제로 안 깨지고 뜨는가" 는 확인이 안 되고 있습니다.
제가 코드를 고칠 때마다 화면이 깨졌는지 대표님이 직접 눌러봐야 알게 됩니다.

**하는 법**

1. Supabase → **Settings** → **API Keys**
2. **anon / public** 열쇠를 복사
   > 🚨 **service_role 이 아닙니다.** anon(공개용) 쪽입니다.
   > service_role 은 모든 권한을 가진 열쇠라 절대 여기 넣으면 안 됩니다.
3. https://github.com/choimog/apple → **Settings**
   → **Secrets and variables** → **Actions**
4. **New repository secret**
   - Name: `SUPABASE_ANON_KEY`
   - Secret: 복사한 anon 열쇠

**확인:** 제가 검사를 한 번 돌려서 `✅ 모든 화면 정상` 이 나오는지 보고드립니다.

# 4단계 🤖 로그인·권한

**왜 5번보다 먼저인가:** 검토 화면은 "이건 같은 책이다" 를 **저장**해야 하므로
쓰기 권한이 필요합니다. 지금 사이트는 읽기 전용 열쇠만 쓰고, 데이터베이스에서
쓰기 권한을 아예 회수해 두었습니다 (`db/rls.sql`).

```sql
REVOKE INSERT, UPDATE, DELETE, TRUNCATE
    ON ALL TABLES IN SCHEMA public
    FROM anon, authenticated;
```

로그인 없이 쓰기를 열면 **주소를 아는 누구나 도서 묶기를 바꿀 수 있게** 됩니다.

**만들 것**

- 이메일 로그인 (Supabase 기능 사용 · 0원)
- 관리자 / 보기 전용 권한 (`profiles` 표는 이미 있습니다)
- **관리자만** 매칭 결정을 쓸 수 있는 데이터베이스 규칙
- 특정 순위표만 외부에 공유하는 링크

**왜: 지금 가장 실질적인 구멍입니다.**

그런데 **사람이 그 결정을 내릴 화면이 없습니다.**
**잘못 묶인 책을 발견해도 대표님이 고칠 수가 없는 상태입니다.**

**만들 것**

- 사람이 누른 결정은 **자동 로직이 절대 못 뒤집게** 저장
- 이미 내린 결정을 되돌리는 기능
