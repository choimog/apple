# 같은 책 찾아내기(매칭) 규칙

이 문서는 **개발 지식이 없어도 읽을 수 있게** 썼습니다.
규칙을 바꾸고 싶으면 `config/matching.yaml` 파일의 숫자만 고치면 됩니다.

---

## 1. 왜 이게 어려운 일인가

세 서점은 **같은 책을 서로 다르게 적어 놓습니다.**

| | 교보문고 | 예스24 | 알라딘 |
|---|---|---|---|
| 제목 | 달러구트 꿈 백화점 (양장본) | 달러구트 꿈 백화점 | 달러구트 꿈 백화점 - 주문하신 꿈은 매진입니다 |
| 저자 | 이미예 | 이미예 저 | 이미예 (지은이) |
| 출판사 | 팩토리나인 | 팩토리나인 | 팩토리나인 |

그냥 글자를 비교하면 **세 권의 다른 책**으로 보입니다.

### 그러면 ISBN으로 묶으면 되지 않나요?

**안 됩니다.** ISBN(책마다 붙는 13자리 국제 고유번호)은
세 서점 **모두 목록 페이지에 노출하지 않습니다.** (2026-08-07 실제 확인)

> ⚠️ 이전에 "알라딘 목록에 ISBN이 있다"고 보고드린 적이 있는데, 그건 제 오판이었습니다.
> `K082130602` 같은 값은 알라딘 내부 상품코드이지 ISBN이 아닙니다.

ISBN을 얻으려면 **도서 상세 페이지에 들어가야 하는데, 그건 금지된 작업**입니다.
그래서 이 프로젝트는 **제목·저자·출판사·출간월 네 가지를 종합해서** 같은 책인지 판단합니다.

---

## 2. 판단 순서 (3단계)

```
1단계  사람이 이미 결정한 게 있나?  →  있으면 그걸 무조건 따름 (자동 로직이 못 뒤집음)
2단계  절대 같을 수 없는 조건인가?  →  하나라도 걸리면 즉시 "다른 책"
3단계  점수를 매긴다 (100점 만점)   →  점수에 따라 병합 / 검토 / 거부
```

---

## 3. 2단계 — 점수와 상관없이 "다른 책"으로 보는 조건

아래 중 **하나라도** 걸리면 점수를 계산하지도 않고 다른 책으로 판정합니다.

| 순서 | 조건 | 이유 |
|---|---|---|
| 1 | **같은 서점 안의 두 상품** | 한 서점이 같은 책을 두 번 올릴 리 없음. 올렸다면 실제로 다른 판형 |
| 2 | **세트 권수가 다름** (전7권 vs 단권) | 사용자 지시: *"세트는 별도로"* |
| 3 | **에디션 표기가 다름** (개정판 / 리커버 / 양장본 …) | 사용자 지시: *"개정판·리커버·양장본은 별도 도서로 취급"* |
| 4 | **핵심 제목 유사도 < 0.60** | 제목이 이 정도로 다르면 나머지가 다 맞아도 다른 책 |
| 5 | **출간월(배본일)이 다름** | 대표님 지시(2026-08-09): *"배본일은 한달만 달라도 다른 책으로 구분해줘"* |
| 6 | **출판사가 다름** | 대표님 지시(2026-08-08). 아래 별도 절 참고 |
| 7 | **정가가 다름** | 대표님 지시(2026-08-11): *"정가가 다르면 확실히 다른 도서"* |

### 7번 — 정가 (2026-08-11 추가)

도서정가제상 **정가는 출판사가 정한 하나의 값**입니다. 그래서 서점이
달라도 같아야 정상이고, 다르면 판형·개정판이 다른 별개 상품입니다.
제목·저자를 아무리 견줘도 안 나오던 답이 정가 하나로 갈립니다.

⚠️ **한쪽이라도 정가를 모르면 거부하지 않습니다.** '모른다' 를
'다르다' 로 바꾸면 값이 아직 없는 책이 전부 갈라집니다.
정가는 2026-08-11 수집분부터 걷기 시작했습니다.

⚠️ **정가가 같다는 전제에서는 제목 규칙을 조금 풀어 줍니다.**
저자·출판사·출간월·정가가 **전부** 같으면
  · 한쪽 제목이 다른 쪽의 앞부분이면 같은 책으로 봅니다 (부제만 붙은 경우)
  · `완역본` 처럼 판형이 아니라 '내용 설명' 에 가까운 말의 차이는 무시합니다
    (`edition_soft_words`)

#### 🚨 어느 서점 정가를 믿을지 고를 수 있습니다

`config/matching.yaml` 의 `price_hard_stores` 에 적힌 서점의 정가만
'갈라내는 근거' 로 씁니다. 지금은 `[1, 2, 3]` (3사 전부)입니다.

**왜 이런 장치가 있나요?** 2026-08-11 에 교보 정가가 이렇게 저장된 적이
있습니다.

```
교보 2,918,000원   vs   알라딘 18,000원      ← '29' + '18,000' 이 이어붙음
교보 1,332,000원   vs   알라딘 32,000원      ← '13' + '32,000'
```

교보 화면은 가격에 이름표(class)가 없어 칸 안 글자를 훑어 읽는데, 태그가
붙어 있으면 할인율과 가격이 한 덩어리가 됐습니다. 그동안 **멀쩡한 짝이
조용히 갈라지고 있었습니다.** 원인은 고쳤지만(태그 사이에 공백을 넣음),
장치는 남겨 뒀습니다. 어느 서점이 또 이상해지면 그 번호만 빼면 됩니다.

**이상해진 것을 어떻게 아나요?** [도서 매칭] 로그 끝에 이렇게 찍힙니다.

```
· 정가 점검 — 양쪽 다 정가를 아는 짝 중, 정가가 달라 갈라낸 비율
    ✅ 교보↔예스24: 12 / 1,204쌍 (1.0%)
    ✅ 교보↔알라딘: 18 / 2,663쌍 (0.7%)
    ✅ 예스24↔알라딘: 9 / 1,880쌍 (0.5%)
```

3사가 같아야 정상이므로 이 비율은 원래 낮습니다. **한 서점 짝만 유난히
높으면** 그 서점 가격을 잘못 읽고 있는 것입니다. 25%를 넘으면 화면에
🚨 와 함께 무엇을 해야 하는지 적어 줍니다.

> 📌 여기서 "에디션 표기"는 제목에서 자동으로 뽑아낸 값입니다.
> 예: `달러구트 꿈 백화점 (양장본)` → 핵심제목 `달러구트꿈백화점`, 에디션 `[양장본]`
>
> 서점마다 `양장` / `양장본` 처럼 다르게 적는 경우가 있어서, 같은 뜻인 표기는
> `config/matching.yaml` 의 `edition_canonical` 에서 하나로 모읍니다.
> (이걸 안 하면 같은 책이 판형 차이로 잘못 갈라집니다)

## 4. 3단계 — 점수 매기기 (100점 만점)

| 항목 | 배점 | 만점 조건 | 부분 점수 |
|---|---:|---|---|
| **핵심 제목 유사도** | 50 | 완전히 같음 | 유사도 × 50점 |
| **대표 저자** | 25 | 정규화 후 완전 일치 | 유사도 0.80 이상이면 15점 |
| **출판사** | 15 | 정규화 후 완전 일치 | 유사도 0.80 이상이면 8점 |

> 🚫 **출판사가 다르면 점수와 상관없이 다른 책입니다.** 아래 &lsquo;즉시 거부&rsquo; 참고.
| **출간월** | 10 | `YYYY-MM` 완전 일치 | 앞뒤 1개월 차이면 5점 |

### 제목 유사도는 어떻게 계산하나요

두 가지 방법으로 각각 재서 **평균**을 냅니다. 한쪽만 쓰면 잘 속기 때문입니다.

1. **순서까지 보는 비교** — 글자가 같은 순서로 얼마나 겹치는지
2. **두 글자씩 끊어서 비교** — `달러구트` → `달러`,`러구`,`구트` 로 쪼갠 뒤 겹치는 비율

### 값이 비어 있으면?

**추정하지 않습니다.** 한쪽이라도 값이 없으면 그 항목은 **0점**이며,
"모르니까 맞다고 치자"는 절대 하지 않습니다. (사용자 지시: *"없는 값은 비워 둘 것"*)

## 5. 점수별 처리

| 점수 | 처리 | 표시 |
|---|---|---|
| **85점 이상** | 자동으로 같은 책으로 묶음 | `high` |
| **65 ~ 84점** | 묶되 **관리자 검토 대기** 표시 | `low` |
| **65점 미만** | 다른 책으로 판정 | 묶지 않음 |
| 사람이 "맞음" 누름 | 무조건 묶음 | `manual` |
| 사람이 "아님" 누름 | **영구히** 안 묶음 (자동 로직이 못 뒤집음) | — |

검토 대기(`low`)로 묶인 책은 화면에서 따로 모아 볼 수 있게 만들 예정입니다 (Phase 5).

## 6. 실제 예시

### 예시 A — 묶임 (95점)

| | 예스24 | 알라딘 |
|---|---|---|
| 원본 제목 | 달러구트 꿈 백화점 | 달러구트 꿈 백화점 - 주문하신 꿈은 매진입니다 |
| 핵심 제목 | `달러구트꿈백화점` | `달러구트꿈백화점` |
| 대표 저자 | `이미예` | `이미예` |
| 출판사 | `팩토리나인` | `팩토리나인` |
| 출간월 | 2020-07 | 2020-07 |

**제목 50 + 저자 25 + 출판사 15 + 출간월 10 = 100점 → 자동 병합**

### 예시 B — 안 묶임 (에디션이 다름)

| | 교보문고 | 알라딘 |
|---|---|---|
| 원본 제목 | 달러구트 꿈 백화점 (양장본) | 달러구트 꿈 백화점 |
| 에디션 | `[양장본]` | `[]` |

**2단계에서 즉시 거부** — 점수를 계산하지 않습니다.

### 예시 C — 검토 대기 (80점)

| | 예스24 | 알라딘 |
|---|---|---|
| 핵심 제목 | `아버지의해방일지` | `아버지의해방일지` |
| 대표 저자 | `정지아` | `정지아` |
| 출판사 | `창비` | (값 없음) |
| 출간월 | 2022-09 | 2022-10 |

**제목 50 + 저자 25 + 출판사 0 + 출간월 5 = 80점 → 안 묶습니다**

> ⚠️ **2026-08-08 규칙이 바뀌었습니다.** 예전에는 이 경우를 "묶되 검토 표시"
> 했습니다. 지금은 **출판사를 한쪽이라도 모르면 85점 이상**을 요구합니다.
> &lsquo;모른다&rsquo;와 &lsquo;같다&rsquo;는 다르기 때문입니다. 출판사가 비어 있다는 이유로
> 다른 출판사의 같은 원작이 뭉치면 안 됩니다.
> 실제로 같은 책이 갈라지는 게 눈에 띄면 `config/matching.yaml` 의
> `publisher_unknown_needs_high` 를 `false` 로 바꾸면 예전 동작이 됩니다.

## 7. 속도 — 8,000권을 다 비교하지 않는 이유

8,000권을 전부 짝지어 비교하면 **3천 2백만 번** 계산해야 합니다.
그래서 **후보를 먼저 좁힙니다(블로킹).**

> **핵심 제목 앞 4글자가 같은 책들끼리만** 비교합니다.

`달러구트꿈백화점` 과 `달러구트꿈백화점2` 는 앞 4글자(`달러구트`)가 같으므로 비교 대상,
`아버지의해방일지` 는 앞 4글자가 다르므로 아예 비교하지 않습니다.

이렇게 하면 비교 횟수가 수만 번 수준으로 줄어 몇 초 안에 끝납니다.

### 이 방법의 한계 (정직하게 말씀드립니다)

앞 4글자가 **다르게** 적힌 같은 책은 **놓칩니다.**
예: `해리 포터와 마법사의 돌` vs `해리포터 1 - 마법사의 돌`
→ `해리포터와` vs `해리포터1` 로 앞 4글자가 갈립니다.

보완책으로 **대표 저자가 같은 책들끼리도** 한 번 더 비교합니다.
위 예시는 저자가 둘 다 `조앤k롤링` 이므로 이 경로로 잡힙니다.

그래도 **저자·제목이 둘 다 크게 다르게 적힌 경우는 놓칩니다.**
이건 자동으로 100% 해결되지 않으며, Phase 5의 수동 병합 화면에서 사람이 처리해야 합니다.

### 또 하나의 한계 — 다른 서점을 다리 삼아 이어지는 경우

"같은 서점끼리는 안 묶는다"는 규칙이 있지만, **간접적으로는 이어질 수 있습니다.**

```
알라딘 싯다르타A ─(같은 책)─ 예스24 싯다르타 ─(같은 책)─ 알라딘 싯다르타B
        └────────── 결과적으로 A 와 B 가 한 무리 ──────────┘
```

실제로는 A와 B가 다른 판형(민음사판 / 문학동네판 등)인 경우가 많습니다.
자동으로 갈라내면 맞게 묶인 것까지 깨질 수 있어서,
**이런 무리는 무조건 `low`(검토 필요)로 표시**하고 사람이 확인하도록 합니다.

실제 2026-08-07 시험 결과: 전체 5,845종 중 이런 경우가 일부 발견됐습니다.

## 출판사가 다르면 무조건 다른 책 (2026-08-08 추가)

### 왜 이 규칙이 생겼나요

민음사·서정시학·다산북스·문학동네의 **『싯다르타』가 한 권으로 뭉쳐** 있었습니다.
같은 원작이어도 **판권·번역·정가·표지가 다른 별개의 상품**입니다.
출판 마케팅 자료에서 이 둘을 섞으면 자료 자체가 쓸모없어집니다.

### 왜 그런 일이 생겼나요

예전에는 출판사를 &lsquo;15점짜리 가산점&rsquo;으로만 봤습니다. 그래서

```
제목 50점 + 저자 25점 = 75점   →  묶는 기준(65점)을 넘음
```

출판사가 완전히 달라도 묶여 버렸습니다. 출간월까지 같으면 85점이 되어
**검토 표시도 없이 자동 병합**됐습니다.

### 지금은 어떻게 하나요

출판사 비교를 **1단계(즉시 거부)** 로 올렸습니다. 점수로는 뒤집을 수 없습니다.

| 상황 | 판정 |
|---|---|
| 민음사 ↔ 문학동네 | 🚫 **다른 책** (점수 계산 안 함) |
| 민음사 ↔ (주)민음사 | ✅ 같은 출판사로 봅니다 (표기만 다름) |
| 민음사 ↔ (값 없음) | ⚠️ 85점 이상일 때만 묶습니다 |

표기 차이는 `publisher_hard_floor`(0.80) 로 흡수합니다. 이 값을
1.0 으로 올리면 글자가 한 자만 달라도 갈라지고, 0.5 밑으로 내리면
다른 출판사가 다시 뭉칠 수 있습니다.

### 괄호로 덧붙인 이름은 &lsquo;같은 뜻인 표기&rsquo; 로 봅니다 (2026-08-12)

서점마다 출판사 이름을 이렇게 다르게 적습니다.

| 교보문고 | 예스24 | 알라딘 |
|---|---|---|
| `윌북` | `윌북(willbook)` | `윌북` |
| `중앙북스` | `중앙북스(books)` | `중앙books(중앙북스)` |
| `느루` | `느루(미래인재컴퍼니)` | `느루` |

글자만 놓고 재면 `윌북(willbook)` 과 `윌북` 은 **0.19** 밖에 안 나옵니다.
문턱 0.80 에 한참 못 미쳐서, 같은 출판사인데 다른 책이 됐습니다.

그래서 이름 하나에서 **&lsquo;같은 뜻인 표기&rsquo; 후보를 여러 개** 뽑아 놓고,
후보끼리 하나라도 겹치면 같은 출판사로 봅니다.

```
윌북(willbook)  →  { 윌북(willbook),  윌북,  willbook }
윌북            →  { 윌북 }
                       └ '윌북' 이 겹칩니다 → 같은 출판사 (1.00)
```

> 🚨 **괄호를 저장할 때 떼면 안 됩니다.** 처음에는 수집할 때 아예 괄호를
> 지워서 저장하려 했는데, `중앙books(중앙북스)` 에서 괄호를 떼면
> `중앙books` 만 남아 **한글 이름이 통째로 사라집니다.** 그래서 저장은
> 원래 이름 그대로 하고, **견줄 때만** 후보를 펼칩니다.
> 덤으로, 이 방식은 **이미 저장된 자료에도 바로 먹힙니다.**
> 다시 수집할 필요 없이 [도서 매칭] 만 돌리면 됩니다.

`창비 ≠ 창비교육`, `김영사 ≠ 김영사on`, `한빛미디어 ≠ 한빛비즈` 는
여전히 다른 출판사로 갈라집니다. 겹치는 후보가 없기 때문입니다.

### 세 표기가 이어지면 한 편으로 봅니다

한 책에 서점마다 이렇게 세 가지가 들어오는 경우가 있습니다.

| 교보문고 | 예스24 | 알라딘 |
|---|---|---|
| `YBM(와이비엠)` | `YBM` | `와이비엠` |

`YBM` 과 `와이비엠` 만 떼어 놓고 재면 **0.00** 입니다. 한글과 영문이라
겹치는 글자가 하나도 없습니다. 그래서 &lsquo;두 개씩 전부 닮아야 한다&rsquo; 로
세면 이 책은 잘못 묶인 것이 됩니다.

하지만 가운데 `YBM(와이비엠)` 이 **두 이름이 같은 곳이라고 서점이 직접
적어 준 증거**입니다. 그래서 이어지면 한 편으로 봅니다.

```
YBM(와이비엠) ─ YBM        (괄호 밖이 같음)
YBM(와이비엠) ─ 와이비엠    (괄호 안이 같음)   → 셋이 한 편
```

이 방식으로 풀린 실제 사례입니다.

| 책 | 세 서점의 표기 |
|---|---|
| ETS 토익 기출입문서 RC | `YBM(와이비엠)` / `YBM` / `와이비엠` |
| 교과서 소설 다보기 2 | `C&A에듀(씨앤에이에듀)` / `C&A에듀` / `씨앤에이에듀` |
| 메이드 인 어비스 14 | `미우(대원씨아이)` / `미우(대원)` / `대원씨아이` |
| 색연필로 그리는 …프랑스 정원 | `도서출판 이종(EJONG)` / `도서출판이종` / `EJONG(이종문화사)` |
| 법정 스님의 말과 글 | `샘터` / `샘터사` / `샘터(샘터사)` |
| 미야모토 시게루의 게임론 | `AK(에이케이 커뮤니케이션즈)` / `에이케이커뮤니케이션즈` / `AK(에이케이)커뮤니케이션즈` |

> ⚠️ **&lsquo;출판사를 아예 모르는 책&rsquo; 을 다리로 삼는 우회와는 다릅니다.**
> 그건 여전히 막습니다(아래 절). 이어 줄 이름이 없는
> `민음사 / 문학동네 / 서정시학` 은 그대로 **세 편**입니다.

### 이미 잘못 묶인 책은 어떻게 되나요

**[도서 매칭]을 다시 돌리면 자동으로 갈라집니다.** 묶기는 매번 처음부터
다시 계산하기 때문입니다.

> 이때 함께 고친 것: 한 덩어리가 여러 개로 갈라질 때, 조각들이 저마다
> 예전 도서번호를 집어가려 해서 **갈라졌는데도 데이터베이스에서는 여전히
> 한 권**으로 남는 문제가 있었습니다. 이제 한 번호는 한 무리만 쓰고,
> 나머지는 새 번호를 받습니다.

### 다른 책을 다리 삼아 우회하는 것도 막았습니다

위 규칙은 **두 권씩 비교할 때** 적용됩니다. 그런데 무리를 만들 때는
이어진 것을 계속 따라가기 때문에, 이런 우회가 가능했습니다.

```
민음사 싯다르타 ─ (출판사 안 적힌 싯다르타) ─ 문학동네 싯다르타
```

가운데 책은 출판사를 모르니 양쪽 다 통과합니다. 규칙은 지켰는데
결과적으로 민음사와 문학동네가 한 권이 됩니다.

그래서 **무리를 다 만든 뒤 마지막으로 한 번 더** 출판사별로 갈라냅니다.

| 상황 | 처리 |
|---|---|
| 민음사 / 문학동네 가 한 무리 | 두 권으로 갈라냅니다 |
| 민음사 / (주)민음사 가 한 무리 | 그대로 둡니다 (같은 출판사) |
| YBM / 와이비엠 / YBM(와이비엠) | 그대로 둡니다 (가운데가 이어 줍니다) |
| 출판사 모르는 책이 끼어 있음 | 점수가 가장 높았던 쪽에 붙입니다 |
| 무리 전체가 출판사를 모름 | 그대로 둡니다 (근거 없이 쪼개지 않음) |

### 정말 고쳐졌는지는 매번 자료로 확인합니다

`crawler/verify_publishers.py` 가 **[도서 매칭] 이 끝날 때마다** 실제
데이터베이스를 읽어서, 한 책 안에 다른 출판사가 섞여 있는지 셉니다.
한 건이라도 있으면 그 책 목록을 찍고 작업을 **실패(빨간불)** 로 끝냅니다.

> 이 확인은 매칭 코드의 `publisher_similarity()` 와 `publisher_hard_floor` 를
> **그대로 가져다 씁니다.** 확인용으로 따로 만들면 나중에 규칙만 바뀌었을 때
> 확인 결과가 조용히 거짓말을 하게 되기 때문입니다.

> 🚨 **2026-08-12 에 실제로 이걸로 멈췄습니다.** 매칭 쪽만 위 괄호 규칙으로
> 고치고, 이 검사기는 옛 잣대를 그대로 두었습니다. 그랬더니 **제대로 묶인
> 359종을 &lsquo;잘못 묶였다&rsquo; 고 신고**하면서 [도서 매칭] 이 통째로 멈췄습니다.
>
> 출판사를 견주는 자리가 **세 군데** 라서 생긴 일입니다.
>
> | 자리 | 하는 일 |

