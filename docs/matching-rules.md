# 같은 책 찾아내기(매칭) 규칙

이 문서는 **개발 지식이 없어도 읽을 수 있게** 썼습니다.
규칙을 바꾸고 싶으면 `config/matching.yaml` 파일의 숫자만 고치면 됩니다.

---

## 1. 왜 이게 어려운 일인가

세 서점은 **같은 책을 서로 다르게 적어 놓습니다.**

| | 교보문고 | 예스24 | 알라딘 |
|---|---|---|---|
| 제목 | 달러구트 꿈 백화점 (양장본) | 달러구트 꿈 백화점 | 달러구트 꿈 백화점 - 주문하신 꿈은 매진입니다 |
| 저자 | 이미예 | 이미예 저 | 이미예 (지은이) |
| 출판사 | 팩토리나인 | 팩토리나인 | 팩토리나인 |

그냥 글자를 비교하면 **세 권의 다른 책**으로 보입니다.

### 그러면 ISBN으로 묶으면 되지 않나요?

**안 됩니다.** ISBN(책마다 붙는 13자리 국제 고유번호)은
세 서점 **모두 목록 페이지에 노출하지 않습니다.** (2026-08-07 실제 확인)

> ⚠️ 이전에 "알라딘 목록에 ISBN이 있다"고 보고드린 적이 있는데, 그건 제 오판이었습니다.
> `K082130602` 같은 값은 알라딘 내부 상품코드이지 ISBN이 아닙니다.

ISBN을 얻으려면 **도서 상세 페이지에 들어가야 하는데, 그건 금지된 작업**입니다.
그래서 이 프로젝트는 **제목·저자·출판사·출간월 네 가지를 종합해서** 같은 책인지 판단합니다.

---

## 2. 판단 순서 (3단계)

```
1단계  사람이 이미 결정한 게 있나?  →  있으면 그걸 무조건 따름 (자동 로직이 못 뒤집음)
2단계  절대 같을 수 없는 조건인가?  →  하나라도 걸리면 즉시 "다른 책"
3단계  점수를 매긴다 (100점 만점)   →  점수에 따라 병합 / 검토 / 거부
```

---

## 3. 2단계 — 점수와 상관없이 "다른 책"으로 보는 조건

아래 중 **하나라도** 걸리면 점수를 계산하지도 않고 다른 책으로 판정합니다.

| 순서 | 조건 | 이유 |
|---|---|---|
| 1 | **같은 서점 안의 두 상품** | 한 서점이 같은 책을 두 번 올릴 리 없음. 올렸다면 실제로 다른 판형 |
| 2 | **세트 권수가 다름** (전7권 vs 단권) | 사용자 지시: *"세트는 별도로"* |
| 3 | **에디션 표기가 다름** (개정판 / 리커버 / 양장본 …) | 사용자 지시: *"개정판·리커버·양장본은 별도 도서로 취급"* |
| 4 | **핵심 제목 유사도 < 0.60** | 제목이 이 정도로 다르면 나머지가 다 맞아도 다른 책 |

> 📌 여기서 "에디션 표기"는 제목에서 자동으로 뽑아낸 값입니다.
> 예: `달러구트 꿈 백화점 (양장본)` → 핵심제목 `달러구트꿈백화점`, 에디션 `[양장본]`
>
> 서점마다 `양장` / `양장본` 처럼 다르게 적는 경우가 있어서, 같은 뜻인 표기는
> `config/matching.yaml` 의 `edition_canonical` 에서 하나로 모읍니다.
> (이걸 안 하면 같은 책이 판형 차이로 잘못 갈라집니다)

## 4. 3단계 — 점수 매기기 (100점 만점)

| 항목 | 배점 | 만점 조건 | 부분 점수 |
|---|---:|---|---|
| **핵심 제목 유사도** | 50 | 완전히 같음 | 유사도 × 50점 |
| **대표 저자** | 25 | 정규화 후 완전 일치 | 유사도 0.80 이상이면 15점 |
| **출판사** | 15 | 정규화 후 완전 일치 | 유사도 0.80 이상이면 8점 |
| **출간월** | 10 | `YYYY-MM` 완전 일치 | 앞뒤 1개월 차이면 5점 |

### 제목 유사도는 어떻게 계산하나요

두 가지 방법으로 각각 재서 **평균**을 냅니다. 한쪽만 쓰면 잘 속기 때문입니다.

1. **순서까지 보는 비교** — 글자가 같은 순서로 얼마나 겹치는지
2. **두 글자씩 끊어서 비교** — `달러구트` → `달러`,`러구`,`구트` 로 쪼갠 뒤 겹치는 비율

### 값이 비어 있으면?

**추정하지 않습니다.** 한쪽이라도 값이 없으면 그 항목은 **0점**이며,
"모르니까 맞다고 치자"는 절대 하지 않습니다. (사용자 지시: *"없는 값은 비워 둘 것"*)

---

## 5. 점수별 처리

| 점수 | 처리 | 표시 |
|---|---|---|
| **85점 이상** | 자동으로 같은 책으로 묶음 | `high` |
| **65 ~ 84점** | 묶되 **관리자 검토 대기** 표시 | `low` |
| **65점 미만** | 다른 책으로 판정 | 묶지 않음 |
| 사람이 "맞음" 누름 | 무조건 묶음 | `manual` |
| 사람이 "아님" 누름 | **영구히** 안 묶음 (자동 로직이 못 뒤집음) | — |

검토 대기(`low`)로 묶인 책은 화면에서 따로 모아 볼 수 있게 만들 예정입니다 (Phase 5).

## 6. 실제 예시

### 예시 A — 묶임 (95점)

| | 예스24 | 알라딘 |
|---|---|---|
| 원본 제목 | 달러구트 꿈 백화점 | 달러구트 꿈 백화점 - 주문하신 꿈은 매진입니다 |
| 핵심 제목 | `달러구트꿈백화점` | `달러구트꿈백화점` |
| 대표 저자 | `이미예` | `이미예` |
| 출판사 | `팩토리나인` | `팩토리나인` |
| 출간월 | 2020-07 | 2020-07 |

**제목 50 + 저자 25 + 출판사 15 + 출간월 10 = 100점 → 자동 병합**

### 예시 B — 안 묶임 (에디션이 다름)

| | 교보문고 | 알라딘 |
|---|---|---|
| 원본 제목 | 달러구트 꿈 백화점 (양장본) | 달러구트 꿈 백화점 |
| 에디션 | `[양장본]` | `[]` |

**2단계에서 즉시 거부** — 점수를 계산하지 않습니다.

### 예시 C — 검토 대기 (80점)

| | 예스24 | 알라딘 |
|---|---|---|
| 핵심 제목 | `아버지의해방일지` | `아버지의해방일지` |
| 대표 저자 | `정지아` | `정지아` |
| 출판사 | `창비` | (값 없음) |
| 출간월 | 2022-09 | 2022-10 |

**제목 50 + 저자 25 + 출판사 0 + 출간월 5 = 80점 → 묶되 검토 표시**

## 7. 속도 — 8,000권을 다 비교하지 않는 이유

8,000권을 전부 짝지어 비교하면 **3천 2백만 번** 계산해야 합니다.
그래서 **후보를 먼저 좁힙니다(블로킹).**

> **핵심 제목 앞 4글자가 같은 책들끼리만** 비교합니다.

`달러구트꿈백화점` 과 `달러구트꿈백화점2` 는 앞 4글자(`달러구트`)가 같으므로 비교 대상,
`아버지의해방일지` 는 앞 4글자가 다르므로 아예 비교하지 않습니다.

이렇게 하면 비교 횟수가 수만 번 수준으로 줄어 몇 초 안에 끝납니다.

### 이 방법의 한계 (정직하게 말씀드립니다)

앞 4글자가 **다르게** 적힌 같은 책은 **놓칩니다.**
예: `해리 포터와 마법사의 돌` vs `해리포터 1 - 마법사의 돌`
→ `해리포터와` vs `해리포터1` 로 앞 4글자가 갈립니다.

보완책으로 **대표 저자가 같은 책들끼리도** 한 번 더 비교합니다.
위 예시는 저자가 둘 다 `조앤k롤링` 이므로 이 경로로 잡힙니다.

그래도 **저자·제목이 둘 다 크게 다르게 적힌 경우는 놓칩니다.**
이건 자동으로 100% 해결되지 않으며, Phase 5의 수동 병합 화면에서 사람이 처리해야 합니다.

## 8. 어디를 고치면 되나요

| 바꾸고 싶은 것 | 고칠 파일 | 항목 |
|---|---|---|
| 점수 배점 | `config/matching.yaml` | `weights` |
| 자동 병합 기준점 (85점) | `config/matching.yaml` | `thresholds.auto_high` |
| 에디션 단어 목록 | `config/matching.yaml` | `edition_words` |
| 출판사에서 뗄 표기 | `config/matching.yaml` | `publisher_words` |
| 비교 후보 좁히는 글자수 (4글자) | `config/matching.yaml` | `blocking.title_prefix_len` |

**이 파일들을 고친 뒤에는 반드시 `매칭 다시 계산` 작업을 한 번 돌려야** 반영됩니다.
(GitHub → Actions → `도서 매칭` → Run workflow)

---

## 9. 묶은 근거는 남습니다

왜 묶였는지 추적할 수 있도록 `book_matches` 표에 근거를 저장합니다.

```json
{
  "title_sim": 0.94,
  "author": "exact",
  "publisher": "exact",
  "pub_ym": "exact",
  "score": 95
}
```

나중에 "이 두 권이 왜 같은 책로 묶였지?" 를 화면에서 확인할 수 있습니다.
