# db 폴더 — 어떤 파일이 무엇인지

Supabase 의 **SQL Editor** 에 붙여넣어 실행하는 파일들입니다.

**실행 방법은 전부 같습니다.**
Supabase → 왼쪽 [SQL Editor] → [New query] → 파일 전체 붙여넣기 → [Run]

> 💡 대부분 **여러 번 실행해도 안전**합니다. 아래 🚨 표시가 붙은 것만
> 조심하시면 됩니다.

---

## ① 한 번은 반드시 실행해야 하는 것 (설치)

| 파일 | 무엇을 하나요 | 언제 |
|---|---|---|
| `schema.sql` | 표(테이블)를 만듭니다. **가장 먼저** | 처음 한 번 |
| `perf.sql` | 순위 계산을 데이터베이스가 하게 합니다 (화면이 빨라집니다) | 처음 한 번 · 순위 계산을 고칠 때 |
| `rls.sql` | 로그인 없이는 자료가 안 보이게 잠급니다 | 처음 한 번 |
| `auth.sql` | 회원·관리자 구분, 매칭 검토에서 판정을 고칠 권한 | 처음 한 번 |
| `price-add.sql` | 정가 칸을 추가합니다 | 2026-08-11 에 한 번 |

## ② 기능을 켤 때

| 파일 | 무엇을 하나요 |
|---|---|
| `share.sql` | 공유 링크 기능 |
| `share-open.sql` | 🚨 공유 링크를 **회원에게도** 열어 줍니다 |
| `archive_schema.sql` | 자료 보관(archive) 표 |
| `force-join.sql` | [강제로 묶기] — 검토 화면에서 책을 직접 이어 붙이기 |
| `publisher-alias.sql` | [출판사 묶기] — 청림Life = 청림라이프 처럼 직접 정하기 |

> ### 🚨 `share.sql` 과 `share-open.sql` 은 **순서가 있습니다**
>
> 두 파일은 **같은 이름의 함수 셋**(`my_share_links` / `create_share_link` /
> `set_share_link`)을 각각 정의합니다. **나중에 실행한 쪽이 이깁니다.**
>
> ```
> share.sql  →  share-open.sql      ✅ 회원 공개가 켜집니다
> share-open.sql  →  share.sql      ❌ 도로 막힙니다
> ```
>
> 2026-08-10 에 대표님이 *"확인표는 다 ✅ 인데 화면은 관리자만 이라고
> 뜬다"* 고 하셨던 원인이 이것입니다. **눈으로는 두 경우가 똑같이
> 생겼습니다.** `tests/test_share_open.sh` 가 진짜 데이터베이스로 이걸
> 매번 확인합니다.

## ④ 🚨 자료를 지우는 것 — 누르기 전에 반드시 읽어 주세요

| 파일 | 무엇을 지우나요 |
|---|---|
| `space-index.sql` | 색인(찾아보기)만 지웁니다 — **자료는 한 줄도 안 지웁니다.** 지워도 화면 내용은 똑같고, 찾는 속도만 달라집니다. 되돌리기 문장이 파일 안에 있습니다 |
| `space-free.sql` | `book_meta` 를 통째로 비우고 색인 하나를 지웁니다 |
| `space-trim.sql` | 순위권 밖 자료 정리 (⚠️ **지금은 쓰지 마세요** — 아래 참고) |
| `meta-slim.sql` | `book_meta` 를 가볍게 만듭니다 |

> ### ⚠️ `space-trim.sql` 대신 [순위 정리] 버튼을 쓰세요
>
> 이 파일은 브라우저에서 2분이 넘으면 끊깁니다(`Failed to fetch`).
> 게다가 SQL 로 하면 1,000줄 한계 같은 함정을 피하기 어렵습니다.
> **GitHub → Actions → [순위 정리]** 로 옮겨 두었습니다. 그쪽을 쓰세요.
> (파일은 기록용으로만 남겨 둡니다)

## 🚨 무엇을 하든 지켜지는 것

- **관리자 열쇠(`service_role`)는 절대 홈페이지 코드에 두지 않습니다.**
  GitHub 금고(Secrets)에만 있습니다.
- 홈페이지가 자료를 바꿀 수 있는 범위는 **매칭 판정과 이 폴더가 연 것뿐**
  입니다. 순위·수집 자료는 홈페이지에서 손댈 수 없습니다.
- 지우는 SQL 은 **되돌릴 수 없습니다.** 걱정되시면 먼저
  GitHub → Actions → [백업] 을 한 번 돌리세요.
