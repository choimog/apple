## 폴더 구조 — 어디를 고쳐야 하나

```
config/          ← ★ 운영 중 고칠 일이 있는 건 대부분 여기입니다
  sources.yaml     수집할 서점·분야 주소 (분야 추가/삭제)
  selectors.yaml   서점 화면에서 값을 뽑는 규칙 (서점이 개편하면 여기)
  matching.yaml    같은 책 묶기 점수 기준
  archive.yaml     보관 기간 · 보관 방식

crawler/         수집·매칭 프로그램 (파이썬)
db/              Supabase 에 붙여넣고 실행하는 SQL
web/             사이트 (Next.js)
tests/           규칙이 깨지지 않았는지 확인하는 시험
docs/            설명 문서
.github/workflows/  자동으로 도는 작업들
```

자세한 지도는 [HANDOVER.md 9번](./HANDOVER.md#9-파일-지도).

## 설계 원칙 (바꾸지 말 것)

1. **서점 공식 API 를 쓰지 않는다.** 알라딘 TTB 포함.
2. **목록 페이지만 수집한다.** 도서 상세 페이지에는 절대 진입하지 않는다.
   목록에 없는 값은 추정하지 않고 비워 둔다.
3. **표지 이미지는 저장하지 않는다.** 서점의 이미지 주소를 문자열로만 저장한다.
   (알라딘 → 예스24 → 교보 순 우선)
4. **robots.txt 를 매번 확인한다.** 금지면 수집을 중단하고 보고한다. 임의 우회 금지.
   (교보 예외는 [HANDOVER.md 6번](./HANDOVER.md#6-절대-지키고-있는-원칙) 참고 — 대표님 승인 사항)
5. **조용한 실패 금지.** 수집량이 평소의 절반 미만이면 성공으로 처리하지 않는다.
   HTML 구조가 바뀌면 빈 데이터를 저장하지 말고 명시적으로 실패시킨다.
6. **부분 실패 허용.** 한 서점이 실패해도 나머지 서점 자료는 정상 저장된다.
7. **멱등성.** 같은 날 다시 실행해도 자료가 중복되지 않는다.
8. **가짜 데이터·목업 금지.** 안 되면 안 된다고 말한다.
9. **비밀키는 코드에 넣지 않는다.** 전부 GitHub Secrets / 환경변수로만.
10. **지우기 전에 확인한다.** 보관 작업은 올린 파일을 **실제로 다시 내려받아**
    지문과 줄 수가 맞는 것만 데이터베이스에서 지운다.
