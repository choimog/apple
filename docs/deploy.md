# 사이트 인터넷에 올리기 (배포)

이 문서는 **개발 지식이 없어도 그대로 따라 할 수 있게** 썼습니다.
한 번만 하면 됩니다. 그 다음부터는 코드를 고칠 때마다 자동으로 올라갑니다.

**걸리는 시간: 약 10분 · 비용: 0원**

---

## 준비물 확인

| 필요한 것 | 어디서 확인하나요 |
|---|---|
| GitHub 계정 | 이미 있음 (`choimog`) |
| Supabase 프로젝트 | 이미 있음 |
| Supabase **anon key** | 아래 1단계에서 복사합니다 |

> ⚠️ **service_role key(관리자 열쇠)는 여기 쓰지 않습니다.**
> 그건 GitHub Actions 에만 넣는 값입니다. 사이트에 넣으면 누구나 데이터를
> 지울 수 있게 됩니다. 아래에서 쓰는 건 **anon key(공개용 읽기 열쇠)** 입니다.

---

## 1단계 — Supabase에서 값 두 개 복사하기

1. https://supabase.com/dashboard 접속
2. 프로젝트 클릭
3. 왼쪽 맨 아래 **Project Settings**(톱니바퀴) 클릭
4. **API** 또는 **API Keys** 클릭
5. 아래 두 값을 메모장에 복사해 둡니다

| 이름 | 생김새 | 설명 |
|---|---|---|
| **Project URL** | `https://xxxxx.supabase.co` | 데이터베이스 주소 |
| **anon / public** | `eyJhbGci...` (아주 긴 글자) | 공개용 읽기 열쇠 |

> ❗ 같은 화면에 있는 **service_role** 은 복사하지 마세요. 그건 관리자 열쇠입니다.

---

## 2단계 — Vercel 가입하고 저장소 연결하기

1. https://vercel.com 접속 → **Sign Up**
2. **Continue with GitHub** 클릭 (GitHub 계정으로 가입하는 게 가장 간단합니다)
3. 로그인되면 **Add New...** → **Project** 클릭
4. `choimog/apple` 저장소를 찾아 **Import** 클릭

---

## 3단계 — 설정 3가지 입력하기 ⚠️ 여기가 가장 중요합니다

Import 를 누르면 설정 화면이 나옵니다. **아래 세 가지를 꼭 확인하세요.**

### (1) Root Directory — 반드시 바꿔야 합니다

기본값은 비어 있습니다. 이대로 두면 **실패합니다.**

- **Root Directory** 오른쪽의 **Edit** 클릭
- `web` 선택 (또는 직접 `web` 이라고 입력)

> 왜? 사이트 코드가 저장소 맨 위가 아니라 `web` 폴더 안에 있기 때문입니다.

### (2) Framework Preset

- `Next.js` 로 되어 있는지 확인 (자동으로 잡힙니다)

### (3) Environment Variables — 1단계에서 복사한 값 넣기

**Environment Variables** 를 펼치고 **두 개**를 추가합니다.

| Name (이름) | Value (값) |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | 1단계의 **Project URL** |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 1단계의 **anon / public** |

> 이름은 **한 글자도 틀리면 안 됩니다.** 대문자·밑줄까지 그대로 복사해서 붙여넣으세요.

---

## 3.5단계 — 보안 설정 ⚠️ 안 하면 화면이 비어 보입니다

Supabase 는 기본 상태에서 사이트가 표를 못 읽거나, 반대로 **아무나 데이터를 지울 수
있는** 상태로 둡니다. 아래를 한 번만 실행하면 둘 다 해결됩니다.

1. https://supabase.com/dashboard → 프로젝트 클릭
2. 왼쪽 메뉴 **SQL Editor** → **New query**
3. 저장소의 **`db/rls.sql`** 파일 전체를 복사해서 붙여넣고 **Run**
   (GitHub → `db` 폴더 → `rls.sql` → 오른쪽 위 복사 아이콘)
4. 아래쪽에 표가 하나 나옵니다. 이렇게 나오면 정상입니다:

   | 표 이름 | rls_켜짐 | 읽기규칙 |
   |---|---|---|
   | books, categories, rankings … | `true` | `1` |
   | profiles, public_links | `true` | `0` |

> 이 설정은 **읽기만 열고 쓰기·삭제는 막습니다.**
> 매일 수집 작업은 '관리자 열쇠'를 쓰므로 영향받지 않습니다.

---

## 4단계 — 배포 버튼 누르기

**Deploy** 클릭 → 1~2분 기다립니다.

성공하면 이런 주소가 나옵니다:

```
https://apple-xxxx.vercel.app
```

**이 주소가 대표님의 사이트입니다.** 즐겨찾기에 넣어두세요.

---

## 잘 됐는지 확인하는 법

주소를 열고 아래 네 가지를 확인하세요.

| 확인할 것 | 정상이면 |
|---|---|
| 첫 화면 | 분야 버튼들과 순위표가 보임 |
| 표지 이미지 | 책 표지가 보임 (회색 무늬면 그 책은 표지 주소가 없는 것) |
| 위쪽 **수집 상태** | 최근 수집 날짜가 초록색으로 보임 |
| **엑셀로 받기** | 눌렀을 때 파일이 내려받아짐 |

---

## 잘 안 될 때

### "데이터를 불러오지 못했습니다" 화면이 나올 때

3단계 (3)의 값 두 개를 다시 확인하세요. 가장 흔한 실수입니다.

- Vercel → 프로젝트 → **Settings** → **Environment Variables**
- 이름에 오타가 없는지, 값 앞뒤에 공백이 붙지 않았는지 확인
- 고친 뒤에는 **Deployments** → 맨 위 항목의 **⋯** → **Redeploy** 를 눌러야 반영됩니다

### 배포 자체가 실패(빨간 X)할 때

거의 항상 **3단계 (1) Root Directory 가 `web` 이 아닌** 경우입니다.

- Vercel → 프로젝트 → **Settings** → **General** → **Root Directory** → `web` 으로 수정
- 저장 후 **Redeploy**

### "보여줄 데이터를 못 찾았습니다" 가 나올 때

화면에 **읽어온 분야 수 / 날짜 수**가 함께 표시됩니다. 그 숫자로 원인이 갈립니다.

| 화면에 나온 값 | 원인 | 해결 |
|---|---|---|
| 분야 **0개** | 사이트가 표를 읽을 권한이 없음 | **3.5단계**(`db/rls.sql`) 실행 |
| 분야는 있는데 날짜 **0개** | 아직 수집을 한 번도 안 함 | Actions → 매일 수집 → Run workflow |

수집을 돌린 뒤에는 GitHub → **Actions** → **도서 매칭** → **Run workflow** 도
한 번 눌러주세요. 그래야 3사 도서가 하나로 묶입니다.

코드를 고쳐서 GitHub 에 올릴 때마다 Vercel 이 **자동으로 다시 배포**합니다.

사이트는 10분마다 새 데이터를 다시 읽어옵니다.
