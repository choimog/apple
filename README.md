## 폴더 구조 — 어디를 고쳐야 하나

```
config/          ← ★ 운영 중 고칠 일이 있는 건 대부분 여기입니다
  sources.yaml     수집할 서점·분야 URL 목록 (분야 추가/삭제)
  selectors.yaml   서점 화면에서 값을 뽑는 규칙 (서점이 개편하면 여기)
  matching.yaml    도서 매칭 점수 기준 (잘못 묶일 때 여기)

crawler/         수집 프로그램 (파이썬)
  recon.py         정찰 스크립트 — 서점 응답 확인용
  common/http.py   요청 간격·재시도 등 예의 규칙

db/
  schema.sql       데이터베이스 표 정의 (Supabase에 한 번만 실행)

web/             웹사이트 (Next.js)

.github/workflows/
  recon.yml        정찰 (수동 실행)
  daily-crawl.yml  매일 자동 수집 (Phase 2에서 추가)
```

## 설계 원칙 (바꾸지 말 것)

1. **목록 페이지만 수집한다.** 도서 상세 페이지에는 절대 진입하지 않는다.
   목록에 없는 값은 추정하지 않고 비워 둔다.
2. **표지 이미지는 저장하지 않는다.** 서점의 이미지 주소를 문자열로만 저장하고
   화면에서 그 주소를 직접 참조한다. (알라딘 → 예스24 → 교보 순 우선)
3. **조용한 실패 금지.** 수집 건수가 평소의 절반 미만이면 성공으로 처리하지 않고
   실패로 기록한다.
4. **부분 실패 허용.** 한 서점이 실패해도 나머지 서점 데이터는 정상 저장된다.
5. **멱등성.** 같은 날 다시 실행해도 데이터가 중복되지 않는다.
6. **비밀키는 코드에 넣지 않는다.** 전부 GitHub Secrets / 환경변수로만.
