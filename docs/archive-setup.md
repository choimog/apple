**【2026-08-08 대표님 결정】 카드 등록 없이 GitHub 에 보관합니다.**

지금 설정은 `config/archive.yaml` 의 `storage: github` 입니다.
운영해 보고 괜찮으면 나중에 `r2` 로 바꾸면 됩니다 (값 한 줄).

## 가) GitHub 보관 — 지금 쓰는 방식 · **설정할 것이 없습니다**

카드도, 가입도, 열쇠 등록도 필요 없습니다. **이미 켜져 있습니다.**

매주 화요일 아침 8시에 오래된 순위를 파일로 빼서 GitHub 에 올리고,
**실제로 다시 내려받아 확인한 뒤에만** 데이터베이스에서 지웁니다.

### 🚨 딱 하나, 대표님이 하셔야 하는 일

**GitHub 보관은 기한이 지나면 파일이 사라집니다.** R2 와 가장 다른 점입니다.

그래서 **사라지기 전에 내려받아 두셔야** 합니다.

보관 기간은 **90일**입니다. 즉 **두세 달에 한 번은 내려받아 두셔야** 합니다.

1. 사이트 **[수집 상태]** 화면에 남은 날짜가 표시됩니다
   > ⏳ 보관 파일이 2026-11-07 에 사라집니다 (90일 남음)
2. 30일 밑으로 떨어지면 **빨간색**으로 바뀝니다
3. **→ 내려받으러 가기** 를 눌러 파일을 받아 PC 나 구글 드라이브에 두세요

한 번 사라지면 되살릴 수 없습니다. 이것만 기억해 주세요.

### 보관 기간 설정은 손댈 필요 없습니다

> **2026-08-09 정정.** 예전 안내에 "400일로 늘리세요" 라고 적어 두었는데
> **제 착오였습니다.** GitHub 의 최대 보관 기간은 **90일**입니다
> (설정 화면에서 그 이상을 넣으면 `Duration must be 90 or less` 가 뜹니다).
>
> 90일은 **이미 기본값**이라 대표님이 바꾸실 것이 없습니다.
> 혹시 예전에 다른 값으로 바꾸셨다면
> Settings → Actions → General → **Artifact and log retention** 이
> `90` 인지만 확인해 주세요.

### 잊어버리셔도 메일이 갑니다

사이트 화면만 믿을 수는 없으니, 매주 금요일 아침에 자동으로 확인합니다.
사라질 날이 **30일 밑으로** 남았는데 아직 안 받으셨으면
**[보관 파일 만료 알림] 작업이 일부러 실패합니다.** → GitHub 이 메일을 보냅니다.

> ⚠️ 이 작업에 빨간 X 가 떠도 **고장난 게 아닙니다.**
> "파일을 받아 두세요" 라는 뜻입니다. 메일 안에 내려받을 주소가 들어 있습니다.

**받으신 뒤에는 알림을 꺼 주세요** (안 그러면 매주 옵니다):

1. GitHub → **Actions** → **보관 파일 만료 알림**
2. **Run workflow**
3. `내려받아 저장을 마쳤습니다` 를 **true** 로 바꾸고 **Run workflow**

이러면 그 파일들에 대한 메일과 사이트 경고가 멈춥니다.
(이미 사라진 파일은 표시되지 않습니다 — 없는 자료를 있다고 착각하지 않도록)

### 잘 되고 있는지 확인

GitHub → **Actions** → **보관소로 옮기기** → **Run workflow**
(`dry_run` 을 `true` 로 두고 실행)

| 로그에 나오는 말 | 뜻 |
|---|---|
| `옮길 날짜가 없습니다` | ✅ 정상. 아직 14일 넘은 자료가 없다는 뜻 |
| `옮길 날짜 N일: …` | ✅ 정상. 준비됐다는 뜻 |

## 나) Cloudflare R2 로 바꾸고 싶어지면

**언제 바꾸면 좋은가:** 파일을 매번 내려받는 게 번거로워지면.
R2 는 영구 보관이라 대표님이 아무것도 안 하셔도 됩니다.

**바꾸는 법:** 아래 1~5단계를 하고, `config/archive.yaml` 의
`storage: github` 를 `storage: r2` 로 고치면 끝입니다.
그때까지 GitHub 에 보관한 파일은 그대로 남아 있습니다.

> ⚠️ R2 는 가입 시 **카드 등록**을 요구합니다.
> 우리 사용량은 무료 한도의 0.012% 라 청구될 일이 사실상 없지만,
> 그래도 부담스러우면 가) 로 계속 쓰셔도 됩니다.

---

## 1단계 — Cloudflare 가입

1. https://dash.cloudflare.com/sign-up 접속
2. 이메일·비밀번호로 가입 (도메인 없어도 됩니다)
3. 이메일 인증 완료

---

## 2단계 — R2 켜기

1. 로그인 후 왼쪽 메뉴에서 **R2 Object Storage** 클릭
2. 안내에 따라 **활성화(Enable)**

---

## 3단계 — 저장 공간(버킷) 만들기

1. **Create bucket** 클릭
2. **Bucket name** 에 정확히 `bestseller-archive`
3. Location 은 기본값 그대로 → **Create bucket**

> ⚠️ 이 버킷은 **비공개**로 두세요.

---

## 4단계 — 열쇠 만들기

1. R2 화면 오른쪽 위 **Manage R2 API Tokens** 클릭
   (또는 왼쪽 **R2** → **API** → **Manage API Tokens**)
2. **Create API Token** 클릭
3. 아래처럼 설정합니다

   | 항목 | 값 |
   |---|---|
   | Token name | `bestseller-tracker` |
   | Permissions | **Object Read & Write** |
   | Specify bucket | `bestseller-archive` 만 선택 |
   | TTL | Forever (또는 기본값) |

   > **Admin Read & Write 를 고르지 마세요.** 필요 이상의 권한입니다.
   > 위처럼 하면 이 열쇠는 그 버킷의 파일만 만질 수 있습니다.

4. **Create API Token** 클릭
5. 나오는 화면에서 **세 가지**를 메모장에 복사합니다

   | 화면에 나오는 이름 | 생김새 |
   |---|---|
   | **Access Key ID** | 짧은 영문+숫자 |
   | **Secret Access Key** | 긴 영문+숫자 |
   | **Account ID** | 주소창이나 화면 위쪽에 있는 32자리 |

   > 🚨 **Secret Access Key 는 이 화면을 닫으면 다시 볼 수 없습니다.**
   > 지금 복사하세요. 놓쳤으면 토큰을 새로 만들면 됩니다.
   >
   > 🚨 **이 값들을 채팅·메일·문서에 붙여넣지 마세요.**
   > 아래 5단계처럼 GitHub Secrets 에만 넣습니다.

---

## 5단계 — GitHub 에 열쇠 등록

1. https://github.com/choimog/apple 접속
2. 위쪽 **Settings** → 왼쪽 **Secrets and variables** → **Actions**
3. **New repository secret** 을 눌러 **네 개**를 각각 등록합니다

   | Name (정확히 이대로) | Secret (값) |
   |---|---|
   | `R2_ACCOUNT_ID` | 4단계의 Account ID |
   | `R2_ACCESS_KEY_ID` | 4단계의 Access Key ID |
   | `R2_SECRET_ACCESS_KEY` | 4단계의 Secret Access Key |
   | `R2_BUCKET` | `bestseller-archive` |

> 이름은 **한 글자도 틀리면 안 됩니다.** 대문자·밑줄 그대로 복사하세요.

---

## 6단계 — 기록표 만들기

옮긴 내역을 남길 표가 필요합니다.

1. Supabase → **SQL Editor** → **New query**
2. 저장소의 **`db/archive_schema.sql`** 전체를 복사해 붙여넣고 **Run**
3. 아래처럼 나오면 정상입니다

   | 표 이름 | rls_켜짐 | 읽기규칙 |
   |---|---|---|
   | archives | `true` | `1` |

---

## 7단계 — 확인만 해보기 (아직 안 옮김)

1. GitHub → **Actions** → **보관소로 옮기기**
2. **Run workflow** 클릭
3. `dry_run` 이 **`true`** 인지 확인하고 실행
4. 끝나면 로그를 봅니다

   - `보관소 접속 정보가 없어…` → 5단계 이름을 다시 확인하세요
   - `옮길 날짜가 없습니다` → **정상입니다.** 아직 30일 넘은 데이터가 없다는 뜻입니다
   - `옮길 날짜 N일: …` → 준비 완료

---

## 8단계 — 실제로 옮기기

30일이 지난 데이터가 생기면 **매주 월요일 오전 8시에 자동으로** 옮겨집니다.
따로 하실 일은 없습니다.

지금 당장 옮기고 싶으면 7단계에서 `dry_run` 을 **`false`** 로 바꿔 실행하세요.

---

## 안전장치 — 데이터가 사라질 걱정은 없습니다

이 작업은 데이터를 지우므로, 아래를 **전부** 통과해야만 지웁니다.

| 안전장치 | 내용 |
|---|---|
| 1 | **최근 14일치는 어떤 설정으로도 안 건드립니다** (코드에 못박음) |
| 2 | 올린 파일을 **다시 내려받아 지문이 같은지** 확인 |
| 3 | **줄 수가 정확히 일치**하는지 확인 |
| 4 | 위가 전부 통과해야만 DB 에서 삭제 |
| 5 | 하나라도 실패하면 **그 날짜는 건너뛰고 지우지 않음** |
| 6 | 접속 정보가 없으면 **아무것도 안 함** |

## 며칠치를 남길지 바꾸고 싶을 때

`config/archive.yaml` 의 `keep_days` 를 고치세요.

- **늘리면**: 사이트에서 더 긴 기간을 볼 수 있지만 Supabase 용량을 더 씁니다
- **줄이면**: 용량이 여유롭지만 사이트에서 볼 수 있는 기간이 짧아집니다
- **14일 밑으로는 내려가지 않습니다** (안전장치)

작업이 끝날 때마다 로그에 **남은 용량 추정치**가 나옵니다.
`400MB` 를 넘으면 경고가 뜨니 그때 `keep_days` 를 줄이세요.
